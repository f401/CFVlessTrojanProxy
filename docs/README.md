# docs

`cf-proxyx` 的文档索引。**顶层只放描述当前系统的文档**；已落地的方案、逐版测量记录、验收过程
统一归档在 [`history/`](history/) 与 [`archive/`](archive/)，进归档的文件开头都会标一行「历史文档，勿照此改代码」。

数字（文件数、类数、单例数、断言数）以门禁为准，不写进本索引——写在这里一定会过期，
`ARCHITECTURE.md` 与 `AGENTS.md` 只保留口径与理由。

## 阅读顺序

1. [ARCHITECTURE.md](ARCHITECTURE.md) —— 分层、一次请求怎么走、状态归属、门禁清单、不变量、类与职责、注释约定。改代码先看这份。
2. [v8.md](v8.md) —— 设计正稿：事实层（五类事实 + TTL）、判定闸门（A/B/C 三级证据）、选路（`score = transport / max(0.25, p)`）、预算、冷启动、迁移、证据分级。
3. [v8实现清单.md](v8实现清单.md) —— 一页可勾选的硬规则（每条带数字与 § 出处）+ H6 缺陷台账（编号 1–215 连续，`tools/doc-audit.mjs` 校验）。
4. [LIMITS.md](LIMITS.md) —— 运行时与免费额度实测、数据面限制、中继可达性边界、状态模型约束、基线数据。
5. [命名约定.md](命名约定.md) —— 成员名规则、单位后缀、枚举、有界表、语义别名、ALLOW 短名理由表、模块级实例准入（`tools/check-names.mjs` 的判据来源）。
6. [本地验证.md](本地验证.md) —— 一条命令跑完全部门禁、本地真请求、发版时机、量测纪律（客户端成功率不能直接当结论）。
7. [审计覆盖.md](审计覆盖.md) —— 审计边界：哪些已系统性看过、哪些只能真机验、哪些判定过不必重开。
8. [重构与技术债.md](重构与技术债.md) —— 控制面重构的验收记录：债务 → 变更 → 验收方式，以及仍需要独立观测的边界。

## 谁在管哪份

| 关心的问题 | 去哪一份 |
|---|---|
| 这个类/函数该放在哪一层，谁持有状态 | `ARCHITECTURE.md` |
| 为什么要这么设计，阈值是怎么定的 | `v8.md` |
| 哪条规则不许破，历史上犯过哪些错 | `v8实现清单.md`（含 H6 台账） |
| 免费计划到底限制了什么 | `LIMITS.md` |
| 变量/方法该叫什么 | `命名约定.md` |
| 这个改动能不能本地验、数字可不可信 | `本地验证.md` |
| 这块要不要再查一遍 | `审计覆盖.md` |
| 这轮重构动了什么、凭什么说没退化 | `重构与技术债.md` |

## 维护规则

- 新增文档：描述当前系统的放顶层并在本文件登记；描述「打算怎么做」的做完之后 `git mv` 进 `history/` 并加归档提示行。
- 活文档（`ARCHITECTURE.md`、`v8.md`、`LIMITS.md`）里提到的 `src/...` 路径、`SC.常量`、裸函数名、类名必须真实存在 —— `tools/doc-audit.mjs` 的 `livingRefs` 逐个核对；`ARCHITECTURE.md` 的类表还要求**每个导出类都在表里**（`classTableMiss`）。
- 同一件事只写一处：硬规则进 `v8实现清单.md`，机制与取舍进 `v8.md`，类与归属进 `ARCHITECTURE.md`，历史证据进 `history/`，重构验收进 `重构与技术债.md`。
