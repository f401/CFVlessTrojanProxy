# v8 设计

> 本文是 v8 的**重写版**：只留结论、规则与证据，删掉了过程日志（那些在 git 历史和 `docs/archive/` 里）。
> 实现时配着看 [`v8实现清单.md`](v8实现清单.md)——那是一页可勾选的硬规则。

---

## 0. 用一句话说清 v8

**v8 把「哪条出口能过这个站点」变成一条可验证、可共享、会过期的事实，然后拿这条事实去挑节点。**

现在的版本（线上 7.86）里，每个 isolate 各自记各自的经验，冷启动时什么都不知道，只能盲选；而且「成功」的判据是 2xx，导致业务 403 和真封锁分不开。v8 改三件事：

1. **事实层**：把「这条中继出口是 v4 还是 v6」「这个站点在这条出口上大概多能过」「这条出口被这个站点拒过」写成带证据等级的记录，放 Durable Object 里全队共用。
2. **判定闸门**：只有「同一时间窗、有对照通道拿到整页」这种有对比的观测才算证据；没有对照就弃权，宁可什么都不写。
3. **选路**：先按硬事实排除（被封锁的、坏掉的），再按代价排序（首字节 + 目标流量的传输时间），族与通过率只做**偏置**，绝不做硬过滤。

**收益（都带条件，见 §8）**：x 这类「会按 IP 族拒绝请求」的站点，首请求成功率从 **40% → 92–96%**（前提是池里至少有一条可用的非 CF 出口），冷启动从 37.7% → 84–90%。
**代价**：冷启动第一条连接最多多等 200ms 读一次事实；每天约 85 次 KV 写（额度 1000）；DO 请求约等于连接数/3（额度 10 万）。

## 1. 要解决的问题

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| P1 | 同一个站点，一会儿 200 一会儿 403 | 出口地址族按连接抽签；v6 出口被目标概率性拒绝 | 8 条中继里 3 条 v4；v4 出口 6/6 与 21/21 过，v6 出口 2/16 |
| P2 | 冷启动前几条几乎必坏 | 事实只在 isolate 内存，新 isolate 从零开始 | 每条 isolate 平均只跑 3 条连接；20% 请求落在冷 isolate |
| P3 | 业务 403 被当成封锁，好节点被踢 | 「成功 = 2xx」；没有对照就下结论 | 7.57：通配封锁把池子标死后成功率 97% → 2/20 |
| P4 | 吞吐最快的节点常常不能过这个站点 | 吞吐与「能过」是两个维度，按一个维度排序必然把坏机器排前面 | 1642 KB/s 的出口对 x.com **0/8**；469 KB/s 的出口 **4/4** |
| P5 | 「最优节点」学不出来 | 每个 isolate 只看到 3 个样本，后验停在先验 | 仿真：本地 `ps` 36.9% ≈ 盲选 40.2% |
| P6 | 额度看着快满了 | 事实若按每请求逐条写，直接把 DO 请求打满 | 2100 请求 = 2100 次写；上限 ≈ 连接数/3 |

## 2. 设计总览

```
用户连接
  │
  ├─① 读事实（冷 isolate：≤200ms，Cache API 优先，DO 兜底；single-flight）
  │
  ├─② 硬过滤：blk[host|relay] 未过期、dead[relay] 未过期 —— 只排这两类
  │
  ├─③ 排序：score = transport(mode) / max(0.08, p)
  │        transport(tput) = ttfb + 512KB / max(32KB/s, cap×64KB/s)
  │        transport(lat)  = ttfb
  │        p = (ok + 4·prior) / (ok + bad + 4)，prior 由 eg 族给出（v4 0.95 / v6 0.5）
  │
  ├─④ 拨号：2.5s 超时、失败最多换一条、CF 托管站点优先非 CF 出口
  │
  ├─⑤ 记账：本条连接的 ttfb / 下行 / 是否 tiny / 是否整页
  │
  └─⑥ 写事实：isolate 结束即冲写（≤3 行），经 commitFact 的闸门
```

**四条不变量**（任何改动都不能破坏）：

1. **永不返回空候选**：全部被排掉时走 `leastBad()`（分最低但历史上出过整页的那条），最差也是直连。
2. **事实只影响排序，不影响协议**：读事实失败就当作没有事实继续选，绝不因为事实层异常而失败请求。
3. **没有对照就没有封锁**：`blk` 必须「同窗口另一通道拿到 ≥20KB 整页 + 三批 ≥60s」。
4. **共享的只能是事实，不能是统计**：`eg`/`blk`/`dead`/`dns`/`cap` 可共享；`ttfb`、绝对 KB/s、每 isolate 的路径统计不共享（换 isolate 就换路径）。

## 3. 事实层

### 3.1 五类事实

| 事实 | 键 | 来源（证据等级） | TTL | 共享 |
|---|---|---|---|---|
| `dns` | host | DoH 查 A/AAAA（**A 客观**） | 24h | ✅ |
| `eg` | relay IP | 经中继打回显服务拿到 IP 字面量（**A 客观**） | 6h（在用 1h） | ✅ |
| `ps` | `host\|relayIP` | 真实连接的成败（**B 统计**，EWMA） | 45min | ✅ |
| `blk` | `host\|relayIP` | 同窗口差分 + 三批确认（**A 差分**） | 90min | ✅ |
| `dead` | relay IP | 连不上 / 证书不对（**A 客观**） | 30min | ✅ |

两条容易搞错的：
- **`ps` 是成功率，不是封锁标记**。它只进分母折价（`/max(0.08, p)`），永远不排除任何候选。
- **`blk` 是唯一的硬排除**，只由 A 级证据写，TTL ≥ 2×cron 避免边界抖动。

### 3.2 写入闸门（`commitFact` 的顺序就是规则）

自上而下，命中即返回：

| 序 | 条件 | 结果 |
|---|---|---|
| 0 | 同键 60s 内已写过 | 丢弃 `R_THROTTLED` |
| 1 | 回显能解析出 IP 字面量 | 写 `eg` |
| 2 | 连接错误（x509/tls/reset/timeout）且中继腿 | 写 `dead` |
| 3 | `429` | 丢弃（只退避） |
| 4 | 4xx 且同窗口无任何通道拿到 ≥20KB | 丢弃（站点级，分不清是谁的问题） |
| 5 | `tiny` + 有 ≥20KB 对照 + 三批 ≥60s + 中继腿 | 写 `blk` |
| 6 | `down > 0` 且非 `tiny` | 写 `ps(ok)` |
| 7 | 零字节且非连接错误 | 丢弃 `R_NO_BYTES` |

三个判据的定义（**只用结构量，不读内容**）：

```
tiny     = down > 0 && down <= 2048 && down < 0.2 × bigTypical[host]
hasBigPeer = 同 120s 窗口内，另一条通道拿到 >= 20KB
confirmed  = 与上一批相隔 >= 60s，且结论一致
```

> 为什么不用「≤64 字节」：封锁页曾经是 4 字节 `IPv6`，现在是 **737B HTML**。绝对值判据一定会被对手改形态废掉，相对自身典型尺寸才稳。
> 为什么业务 4xx 不会被误判：`api.github.com` 的 415 带 1277B 正文，`bigTypical` 也是 1277B，比值 ≈ 1，不满足 `tiny`。

### 3.3 存储：DO 的一张表

```sql
CREATE TABLE facts (
  kind TEXT NOT NULL,   -- dns | eg | ps | blk | dead | cap
  k    TEXT NOT NULL,   -- dns: host   eg/dead/cap: relayIP   ps/blk: host|relayIP
  at   INTEGER NOT NULL,
  j    TEXT NOT NULL,   -- 短键 JSON（ps 单行 < 40B）
  PRIMARY KEY (kind, k)
) WITHOUT ROWID;
CREATE INDEX idx_facts_at ON facts (kind, at);

-- 唯一写入口：旧证据永不覆盖新证据（严格 >，相同 at 也丢弃，防两个 isolate 乒乓）
INSERT INTO facts (kind, k, at, j) VALUES (?, ?, ?, ?)
ON CONFLICT (kind, k) DO UPDATE SET at = excluded.at, j = excluded.j
WHERE excluded.at > facts.at;
```

容量：`dns 512 / eg 512 / ps 512 / blk 1024 / dead 256 / cap 256` 行。读必须**按 kind 分片**（`?s=eg&since=`）——实测 1000 行 = 82KB，整库最坏 ~250KB，一次全量读会吃掉免费计划几十毫秒的 CPU 预算。

### 3.4 额度账

| 项 | 用量 | 额度 | 说明 |
|---|---|---|---|
| KV 写 | ~85/天 | 1000/天 | `px:seed`、`px:pool:<gen>`、`snap`、`usage:snap`、`users` |
| KV 读 | ~500/天 | 10 万/天 | 冷启动 + 订阅 |
| DO 请求 | 连接数/3 | 10 万/天 | 上限 ≈ 30 万连接/天；超了按 `k` 抽样写 |
| connect 并发 | 6 | 6 | 真正的瓶颈，见 §5 |
| 子请求 | ≤48/轮 | 50 | 探活走 `connect()`，**不占**这一项 |

> 事实层不是额度瓶颈：**先撞顶的永远是「请求/天」本身**。真正的约束是 `connect()` 的 6 个并发名额。

## 4. 判定：什么算封锁，什么不算

四类现象必须分开，混在一起就是 7.57 那次事故的原因：

| 现象 | 长相 | 怎么判 | 动作 |
|---|---|---|---|
| 业务 4xx | 带站点自己的页面（1277B 的 GitHub JSON、932B 的 example 页） | 相对自身典型尺寸**不算小** | 原样透传，永不封锁 |
| 族级拒绝 | 737B HTML，正文提 `IPv6` | 同窗口有另一族出口拿到整页 | 只降权（`ps`），不写 `blk` |
| 单 IP 封锁 | 与族无关，某条出口稳定失败 | 三批差分确认 | 写 `blk[host\|relay]`，90 分钟 |
| 中继自身坏 | 证书错 / RST / 超时 / 回自己的页面 | 连接层错误 | 写 `dead`，30 分钟 |

判定协议（A/B/C 三级）：

- **A 级**（可写 `blk`）：同窗口两条腿——腿 A「新鲜 `eg=4` 且拿到 ≥20KB」，腿 B「新鲜 `eg=6` 且只拿到 `tiny`」；**两个独立批次（≥60s）结论一致**。
- **B 级**（只进内存，±10 分钟）：单批 `tiny` + 同窗口整页对照。用于把「弱」压下去，但不能硬排除。
- **C 级**（只计数）：单次观测、429、直连腿的 4xx、>1KB 的非站点页。

三条禁令：
1. **直连腿的 403 永不进共享事实**——那是 CF 边缘的出站身份，归属不到稳定对象。
2. **全通道 4xx 永不写封锁**——那时我们分不清「站点拒绝所有人」和「这批出口被封」。
3. **`blk` 永不外发到其他站点**，也永不外发通配键（`*|relay`）。7.57 用通配封锁把整池标死：97% → 2/20。

## 5. 选路

### 5.1 代价函数

```
p        = (ok + 4·prior) / (ok + bad + 4)        prior: eg=4 → 0.95, eg=6 → 0.5, 未知 → 0.5
score    = transport / max(0.08, p)
tput     = ttfb + 512KB / max(32KB/s, cap × 64KB/s)   // cap 是相对池内中位数、已过噪声门
lat      = ttfb
```

三条设计理由：
- **`p` 进分母而不是加常数**：`p=0.125` 的通道代价被放大约 8 倍，足以让它排到后面，但**永远排不完**（仍能被选中，池子不会枯竭）。
- **`cap` 是比值不是绝对值**：绝对 KB/s 换 isolate 就不可比（同一中继跨轮摆动 0.82–1.74x）。
- **噪声门**：同一中继两次测得的极差 ≤1.5x、且与池内中位数差 <2x 时，视为没有可学差异，不记 `cap`；此时 `/health` 标 `thr:"link-bound"`，按 `ttfb` 排即可——**不假装在优化吞吐**。

### 5.2 排序链

```
硬过滤（blk、dead）
  → 负记忆（负面证据，10 分钟）
  → 正记忆（最近出过整页，10 分钟）
  → score 升序
  → ip 字典序（保证确定性，测试可断言具体哪条）
```

`eg` 只出现在 `prior` 里（+0.25 量级的偏置），**不单独决定**：仿真里「只按出口族确定性选择」只有 **14.3%**，比盲选 40.2% 还差——因为一旦钉住「族对但站点拒」的那条就永久钉死。

### 5.3 冷启动三条路

| 情形 | 动作 | 代价 |
|---|---|---|
| warm（`alive` 非空、事实有） | 正常排序 | 0 |
| cold + 有缓存 | **最多阻塞 200ms** 读事实（Cache API 优先） | 首字节 +≤200ms，收益 40%→90% |
| cold + 无缓存 | 不阻塞，后台补 1 条回显探测（受波次限流） | 0，但这一条请求仍盲选 |

预算算术：`命中率 ≈ 1 − exp(−λ · TTL/60)`。个人自用（λ<0.5/分）命中率天然只有 ~33%，所以 200ms 这条预算必须保留——它在高流量下代价为 0，低流量下值 9 个点。

### 5.4 康复与探索

- **康复通道**：每 20 条请求放 1 条走「分数最低、但历史上有过整页」的中继。没有它，被误判的节点永远拿不到样本、永远恢复不了（D12）。
- **同质化检测**：候选 `p` 的 `max/min < 1.5` 时视为同质，改走轮换——弱池会被 `ps` 坍缩成个位数成功率并锁死。
- **探索**：8% 的请求不看分数（无记忆的候选优先），用于发现新出口。

## 6. 预算与并发

免费计划的三个额度，按约束强度排序：

| 约束 | 数值 | 后果 |
|---|---|---|
| 并发 `connect()` | **6** | 最硬。40 并发时 14 次探测 × 250ms ÷ 6 ≈ 583ms，p95 从 250 → 675ms |
| DO CPU | 几十毫秒 | 单发 TLS 握手装不下（这条已放弃，见 §11 #19） |
| 子请求 | 50/轮 | 探活走 `connect()`，不占；`refill + tfb` 只占个位数 |
| DO 请求 | 10 万/天 | 连接数/3，超了抽样 |

因此：
- **探测按波次限流**：一波用户连接最多 2 次探测，超出的直接用事实里最稳的那条；`/health` 暴露 `probeWaveUsed` 与 `connectWaitMs`。
- **`readFacts` 必须 single-flight**：同一 isolate 内并发读共享一个 Promise，否则等于「每条连接各读一次」。
- **写入批量**：3 连 isolate 攒不到 16 条，所以**结束即冲写**（≤3 行）；超过 20 万连接/天按 `k = ceil(连接数/30万)` 抽样，丢弃计入 `psDrop`。

## 7. 冷启动与客户端订阅

冷启动的残差不在服务端能修的那一半，所以订阅也要参与。结构（每个模式各一套竞速组，共用会让吞吐组混进取速条目）：

```
🅰 模式 (select)
 ├─ 🚀 吞吐优先 (fallback)
 │   ├─ 📡 目标实测（仅 ?tu= 时发）
 │   ├─ 🌐 入口竞速（url-test，server 是 CF 边缘 IPv4 字面量）
 │   ├─ 🔁 中继竞速（url-test，条目带 px=1&rx=<ip>）
 │   └─ 📛 域名入口（回退，v6 网络下必 403，只作最后手段）
 └─ ⚡ 速率优先 (fallback) 同上
```

- **入口竞速组只证明「能到 CF」**：实测它与「不挂组」逐位相同（52.6% / 54.6% / 47.8%），看不到出口族。真正有用的是 `?tu=` 目标实测组。
- **`?tu=` 必须「连测 2 次通过才健康」**：坏中继单次测试有 12.5% 概率蒙对。6 成员+连测 2 = 92.6%，10 成员+连测 2 = 97.4%，10 成员+连测 3 = 98.7%。mihomo 没有「连续 N 次」原语，需服务端 `/health?probe=2` 配合。
- 预算：默认 ≤36 条、`?full=1` ≤60 条；开关 `?e=0` 关入口块、`?r=0` 关中继块、`?ei=4..16` 入口数、`?p=vless|tj|both`（默认 vless）、`?tu=<url>` 开目标实测。
- 健康检查节奏：入口 180s / 中继 300s / 目标实测 300s 且成员 ≤4，合计约 8000 次/天（Worker 免费额度的 8%）。
- 已知局限：`?tu=` 会被**假 200**（nginx 假页）骗过——这一条没有通用解法，不假装能修。

## 8. 承诺与边界

| 条件 | 首请求成功率 | 冷启动 |
|---|---|---|
| 池里有 ≥2 条可用非 CF 出口（`eg=4`） | **92–96%** | 84–90% |
| 只有 1 条可用非 CF 出口 | 93.8% 但不冗余（降级态） | 同上 |
| 只有 v6 出口 / 全部被拒 | **≤14%** | ≤14% |
| 业务 4xx 站点（`api.github.com` 类） | ≥97%（原样透传） | — |

- 弹性实测：好出口 0 → 1 条值 **82 个点**，1 → 2 条只值 0.9 个点，3 条以上不加分 ⇒ 目标是 2 条，不是越多越好。
- 天花板 97.9%：25% 中继「族对但站点拒」+ 8% 探索 + 2% 连不上。
- **不承诺**：每次都挑到最优（2k~3k 池子做不到）、并发下 100%、吞吐一定比直连快（客户端腿是瓶颈时谁都慢）。
- 体感口径用 `good3s`（成功且 ≤3s）：盲选 32.4% → v8 68.2%。

## 9. 迁移六步

| 步 | 内容 | 成功率 | 验收 |
|---|---|---|---|
| S1 | 只加事实层（`eg`/`dns` 采集与落库），**选路不变** | 44.6 → 45.5% | 指标必须**不变**（变了说明你顺手用了 `eg`） |
| S2 | `eg` 偏置 + 共享 `ps` | **95.9%**（+50.4） | 两小时内见 +30 点 |
| S3 | `blk` 硬排除 | 97.8%（+1.9） | 空候选率 <0.1% |
| S4 | 冷启动读事实 + 200ms 预算 | 97.8%（+0） | `p95ok` 不涨过 60ms |
| S5 | 订阅新结构 + 竞速组 | 97.8%（+0） | 组内不涨就关 |
| S6 | 清理旧表（`verdict`/`judge`/`relperf`/`relay-health` 四合一） | — | 行为逐位等于 S5 |

每步回滚线：S1 掉 >6 点、S2 两小时不见 +30 点、S3 空候选 >0.1%、S4 `p95ok` 涨 >60ms、S5 组内不涨 —— 关掉后必须**逐位等于上一步**。

## 10. 可观测性

| 指标 | 定义 | 为什么不能用别的代替 |
|---|---|---|
| `firstTry` | `down > 0` | 连通率，含封锁页 |
| `firstPage` | `down >= 4096` | 拿到真页面；和 `firstTry` 的差就是「出口被拒」 |
| `ftGray` | 2048 < down < 4096 | 判据灰带，计数观察是否需要调阈值 |
| `p95all` / `p95ok` | 全体 / 只算成功 | 成功率上升时 `p95all` 会**变差**（封锁页只要 60ms），只看 `p95ok` |
| `good3s` | 成功且 ≤3s | 体感口径 |
| `aliveCnt` / `eg4Cnt` / `srcFail` | 池子健康 | 补货是否有效只能靠这三个数 |
| `psDrop` / `factSkip` | 写入丢弃 / 闸门拒绝 | 学习链断没断的唯一证据 |

调试端点：`?rt=<host>`（该站点的候选与代价）、`?blk=<host>`（封锁行）、`?plan=1`（本轮预算分配）、`?facts=1`（事实层快照）、`?tfb=<host>`（探测）、`?edge=1`（入口探测，服务端仅供诊断）。

## 11. 已证伪的说法（别再写回设计里）

| 错的说法 | 为什么错 | 现在怎么做 |
|---|---|---|
| 客户端 IP 会随隧道透传给目标 | 隧道是**原始 TCP**，Worker 自己 `connect()` | 客户端族只经「落哪个 POP」间接影响 |
| 钉 v4 入口就能解决 403 | 实测钉完仍有一半 403 | 靠 `eg` + `ps`，不靠客户端 |
| 「3/8 是 v4」是稳定属性 | 同出口 2/5 交替翻转（D11） | `eg` 带 TTL + 在用时 1h 复检 |
| 封锁页是 4 字节 `IPv6` | 现已是 737B HTML | `tiny` 用相对尺寸 |
| `p(通过|v6)=12.5%` 是常数 | 只有 2/16 样本 | 只当方向，不当常数 |
| 本地 `ps` 够用 | 36.9% ≈ 盲选 | `ps` 必须共享 |
| 只按出口族确定性选择 | 14.3%，比盲选更差 | 族只做偏置 |
| 攒 16 条再写 | 3 连 isolate 永远攒不满，丢 100% | 结束即冲写 |
| 通配封锁能跨站点省事 | 7.57：97% → 2/20 | 只写 `host\|relay`，三批确认 |
| 「快点探测就能补上供给」 | K=4→8 只 +0.25 点 | 供给靠池子大小（目标 16） |
| 用「2xx」判成功 | 业务 403 会被当失败 | `down > 0` |
| 探活会吃满子请求额度 | 探活走 `connect()` | 真正的瓶颈是 6 个并发 connect |
| 服务端能判定「客户端→边缘」质量 | Worker 打自家域名必 522 | 只能客户端实测 |

## 12. 证据分级

- **A 级（生产实测）**：出口族 3/8 v4；出口族 1.5h 内稳定；盲选 40%（8/20）；钉 v4 21/21；封锁页 737B；业务 4xx 零误封（判定表 0 行）；proxyip 本地 0/80；源可达 1–3/6；吞吐 1642 vs 275 KB/s；噪声 0.82–1.74x、Spearman −0.49。
- **B 级（仿真，输入取自 A）**：v8 94.7% vs 盲选 40.2%；族硬过滤 14.3%；本地 `ps` 36.9%；`blk` 三批假阳性 0.01%；冷启动天花板 97.9%；`/health` 竞速组与无组等价；40 并发 p95 675→250ms；`p95` 偏倚 +74ms/+7ms；S2 +50.4 点；恢复需 29–40 次成功；攒 16 条丢 100%；唯一 v4 被拒 1.3→9.4%；0→1 值 82 点；缺货率 28.5%。
- **C 级（推理）**：只做方向，不给数字。
- **未验证**：客户端 v6 路径（本地无 v6，只能用户用 FlClash 复测）、`?tu=` 的假 200、X 侧拒绝的确切机制、`d=5%/h` 的样本量。

引用规矩：A 照抄；B 连输入一起引用；C 只做方向；标不出等级就删。
