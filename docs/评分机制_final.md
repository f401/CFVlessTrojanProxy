# 评分机制（最终版）

> 一句话：**分数 = 这个节点平均让用户多等多少毫秒。**
> 两种模式共用一套观测，只有最后一步加权不同。

---

## 1. 观测：每个 (colo, node) 一份统计（per isolate，不外传）

```js
S = {
  tcp, tls,          // 探活握手 EWMA(α=0.3)      先验 250 / 60 ms
  pN, pF,            // 探活次数 / 连续失败
  okW, failW,        // 成功/失败权重（按半衰期衰减）
  tS, tF,            // 成功率样本（窗口用 WIN_HL=3min 指数衰减）
  eCloseP, eCloseD,  // 上游"连上就关"的次数（proxyip 可疑判定）
  stallMs, runMs,    // 背压累计毫秒 / 连接总毫秒（都衰减）——碰到的每条连接都要累加 runMs
  pSum, pSumSq,      // 真实首字节(ttfb) 的 EWMA 均值 / MAD（抖动 = MAD×1.4826）
  msLocal,           // pSum 的取整投影（面板用）
  cus, cusB,         // 变点累积量：延迟（ms 当量）/ 吞吐（log2 倍数），越线即冻结或重置直方图
  hist[12], sumW, sumW2, recentBytesW, lastSampleAt, capBps,  // 吞吐直方图与置信度原料
  at, failStreak, blackUntil, freeUntil
}
```

**不在 KV 里**（v6.35 起）：`px:seed` 只存候选名单 `{k,h,p,cc}`，不存任何统计。
每个 isolate 的最优节点可能不同，跨 isolate 传统计等于把别人的体感当自己的样本
（见 docs/节点选择仿真.md §32）。

### 1.1 衰减（唯一入口）

```js
const HL = 6 * 3600e3;
function decay(s, now) {
  const k = Math.pow(0.5, (now - (s.at || now)) / HL);
  s.okW *= k; s.failW *= k; s.stallMs *= k; s.runMs *= k;
  s.sumW *= k; s.sumW2 *= k * k; s.hist = s.hist.map(x => x * k);
  s.at = now;
}
```
更新前、读分前都调一次。**不存在终身计数。**
`pSum/pSumSq` 例外：它们是 EWMA 矩（均值与 MAD，记忆本就按 0.6/0.4 衰减），再乘 `k` 会重复衰减；
`pN` 只用来算 `latN`（延迟样本量），也不当权重用。`cus/cusB` 是累积量，同样不参与衰减。

### 1.2 概率（Beta 先验 + 不确定性溢价）

```js
pFail  = (a + failW) / (a + b + okW + failW) + 0.5*√var*(1-e^(-N/4))   // a=1,b=9 ⇒ 无数据 0.10
pStall = (stallMs + 50) / (runMs + 1000)                               // 无数据 0.05
avail  = N>=30 ? WilsonLowerBound : (ok+1)/(n+2)
```

## 2. 两个代价函数

### 2.1 延迟估计（两模式共用）

```js
probeL = tcp + tls*1.2 + max(0, tls - 2*tcp - 30)*2        // 探活：握手 + 疑似重传
realL  = pSum || msLocal || 0                              // 真实首字节（ttfb）均值
realC  = min(realL, probeL + 1500)                          // 单条坏连接不定生死
realW  = min(REAL_W=8, okW)                                 // 按样本数加权，不卡阈值
Lobs   = (probeL*PROBE_W=2 + realC*realW) / (2 + realW)      // 探活只留 2 份底仓
latencyMs = realW > 0 ? Lobs : confL*probeL + (1-confL)*Lprior
jitMs  = pSumSq * 1.4826                                    // 抖动 = MAD×1.4826（σ 的一致估计）
```

`pSumSq` 存的是 **MAD**（`EWMA(|x-base|)`）而不是方差：一条 5 s 的怪连接会把方差抬到
秒级，把节点的抖动分永久抬高；MAD 对单点不敏感，实测同一条 5 s 样本只把 `jitMs` 从 0 抬到 ~240 ms。

### 2.1.1 变点检测（CUSUM）

```js
// nsLatency：连续偏高才累加；两条 4 倍的慢样本就冻结 60 s，比失败阶梯早好几个样本
cus = max(0, cus + ms - base - max(K=30, base*0.25));
if (cus > H=300) { cus = 0; freeUntil = now + 60000; pSum = (pSum + ms)/2; }
// nsSpeed：吞吐掉到 60% 以下才累加 log2(倍数)，越线就把直方图按 0.2 缩放并改写 capBps
cusB += log2(prevCap/bps) - 0.3  或  cusB = max(0, cusB - 0.15);
if (cusB > 1.2) { hist *= 0.2; sumW *= 0.2; sumW2 *= 0.04; recentBytesW *= 0.2; capBps = bps; }
```

单条怪样本不该翻案（阈 `K=30` 挡掉），持续漂移则必须立刻挪走流量。
`pSum = (pSum + ms)/2` 是"认账"：以新水位为基准，否则旧基线会一直报警。

ttfb 是**主信号**：每条成功连接一个样本，比探活"能不能连上"更接近体感，
也自动纠正"探活撒谎"（报 25 实际 350）与"反向撒谎"（报 420 实际 60）。

### 2.2 速率优先 `lat`

```js
xfer    = capBps ? sz/capBps : sz/PRIOR_BPS                   // 典型请求的传输时间（sz 默认 160 KB，先验 78ms）
          // 比先验快 ⇒ 随样本年龄线性贬值；比先验慢 ⇒ 原样保留（别把慢样本"忘"成先验）
          // capBps=0（没测过带宽）时必须直接用先验，否则 160KB/8KB=20 秒会淹没整池分数
v_lat = latencyMs + xferMs + 0.5*jitMs
      + 5000*pFailRisk + 2500*pStall;
```

### 2.3 吞吐优先 `tput`

```js
E10MB = confB*(sz/capBps) + (1-confB)*(sz/PRIOR_BPS)         // tput 默认 sz = 10 MiB
v_tput = E10MB + 0.5*latencyMs + 5000*pFailRisk + 2500*pStall;
```

### 2.4 目标流量 S（`?sz=i|s|b`）

同一个节点"开网页最快"和"下大文件最快"可以不是同一个：低延迟窄带的节点赢在小请求，
高延迟宽带的节点赢在批量传输。所以代价函数里的 S 不是常数，客户端可以按连接声明：

| `?sz=` | 字节 | 典型用途 |
|---|---|---|
| （不写） | 160 KB（lat）/ 10 MiB（tput） | 默认 |
| `i` | 64 KB | 交互：API、单页、代理协议握手 |
| `s` | 1 MiB | 流媒体：缓冲一小段 |
| `b` | 16 MiB | 批量：下载、更新、备份 |

实现上只多一个参数：`scoreParts(k, mode, now, withGate, bytes)` 里把 `sz` 代进去，
`pick()` 从连接状态 `st.sz` 取，抽样器（`pickThom`）跟着用同一套分数。
仿真里"同一池子，64 KB 与 16 MB"两个场景：16 MB 下基线一直选低延迟窄带节点，
代价 **6.87x**；按 S 打分后 **1.53x**（93% 时间选对），64 KB 场景也顺带从 1.17x 降到 1.07x。

`capBps` 来自 **带衰减的直方图**（12 桶 log2，从 16 KB/s 起）：
`cap = min(p90, p50*2.5)` —— 分位对等比衰减免疫，所以衰减后不用重算；
`p90` 防"最低保证"，`p50*2.5` 防"一次突发封神"。

> "最大速度"= 能力上限 → 用 p90 不用均值；均值会被"客户端限速/服务器抽风"拖低。

## 3. 置信度与收缩

```js
nEff   = sumW² / sumW2;                                  // 有效样本数（不是次数）
confL  = 1 - Math.exp(-latN / 4);                        // latN = pN + okW
confB  = 0 除非 nEff>=3 且 recentBytesW>=3MiB 且 样本<=24h
         → min(1, recentBytesW/3MiB) * (1 - e^(-nEff/4))
priorBps = 2 MB/s                                        // 固定先验（v6.35 起不再借别处的 seedBps）
```

- 新节点**向先验靠拢**：lat 用探活+先验混合（`confL`），tput 用 `e10Prior`（先验 5 秒）
- 吞吐要"有效样本数 ≥3 且累计 3 MiB"，否则一个 40 KB 的样本就能封神

## 4. 两条单向闸门（只加不减）

```js
if (pStall > 0.25 && N >= 5)                            score += 400;   // 明显卡
if (m === "tput" && confB > 0.25 && capBps < 8*1024)    score += 400;   // 实测极慢（只在 tput 模式）
```
闸门**不会抬升任何节点**，只做降级。

## 5. 选择状态机（v6.35：单层抽样）

`Selector.pick` 的顺序：① 站点画像 → ② 冷启动探索（只在还没样本时）→ ③ **单层 Thompson**（两模式共用）→ ⑤ 粘滞游标兜底。

```js
// ③ 单层抽样（src/px/ts.ts pickThom）
cands = candsFor(mode)                        // 分数榜前 TS_K=64
      ∪ 未测节点（最多 TS_EXTRA=64 个）          // 否则新节点永远排在分数榜后面
sd    = √(sdL² + sdB² + sdF²)
sdL   = latencyMs / √latN                     // 延迟测不准
sdB   = (1-confB) × 0.6 × (tput ? e10Ms : xferMs)   // 带宽没测过
sdF   = 5000 × √(p(1-p)/(n+3))                // 失败率样本少（n=0 时 ≈865ms）
qMs   = inflight(k) × (tput ? e10Ms : xferMs) // 排队项：前面还有几条在传
v     = score + qMs − TS_BETA×sd + gauss()×TS_SD_MIN // 排队 + 乐观面 + 抽样噪声
剪枝   : 丢掉 v > min(score) + TS_BAND 的臂     // 300 个候选不能全池摊流量
```

**排队项（v6.36.1）**：`S.inflight` 只记"当前真正在传"的连接数，所以单连接场景下
`qMs` 恒为 0、与旧公式逐位等价；只有并发把某个节点压到排队时才会把它往后推。
它取代了原来"`inflight≥2` 且分数在 1.5× 内就硬换手"的二值条件——那个条件在
3 条并发时就失效，而 `qMs` 是连续量：第 2 条请求看到 +1×服务时间，第 3 条看到 +2×。
仿真里只有 `12/s 2MB`（需求 24MB/s > 单节点 40MB/s 的一半）这类真正饱和的场景有差：
3.29x → 3.19x；`12/s 256KB` 与 `2/s 2MB` 逐位不变。

**一个抽样器取代原来三层**（探索率 5–10% + 加权抽签 K=12/T=20|50 + 延迟 Thompson）。
三层叠加的问题是"探索预算说不清"：影子 5% + 抽签摊给 12 名 + Thompson 又按后验摊，
实际分给第 2 名的流量在 5%–40% 之间漂。抽样器只有两个旋钮（`TS_BETA` 乐观度、
`TS_BAND` 剪枝带宽），期望流量 ≈ 后验胜率，可以直接解释。

- 失败率**不再降级成门槛**：它以 `5000×pFailRisk` 留在分数里，只是用 `sdF` 表达"样本少 = 不确定"，
  于是"探活撒谎"的节点会先被抽几次、用真实样本纠正，而不是靠 `bestFor` 兜底硬记住。
- `TS_BETA=0.5` 时 20 节点场景会早停在次优节点（1.40x vs 1.32x），所以默认 **0.8**；
  再往上（1.2）单测里"王者拿不到流量"——乐观面不能大到让"样本少"长期压过"更好"。
- **⑤ 粘滞游标只做三件事**：面板/health 展示、`maybeSwitch` 的滞回/驻留/预算记账、
  失败回滚（`onFail` 只对 `k === S.curs` 生效）。**不能拿游标推断线上流量分给了谁。**
- **⑥ 兜底：全池冷却时也必须给出一个节点**。`leastBad()` 按"恢复时间最早、再按代价最低"挑，
  只在 `S.alive` 为空时返回 `""`。理由是空串会让 `session` 直接 `cnt("dead")` 放弃这条连接，
  哪怕池子里还有节点只是暂时在冷却期。仿真里这条兜底把 `12/s 2MB`（24 MB/s 需求打 6 节点池）
  从 30% 的连接"无节点可用"降到 0：代价 3.19x → **2.36x**，p95 14.5x → 3.4x。
- **v6.42 起只有这一条选路算法**：旧的「探索率 + 加权抽签（`ROUTE_T_*`）+ 延迟 Thompson（`LAT_TS`）」
  三层路径已整段删除（连带 `trial()` / `buildWatch()` / `pickByScore()` / `pickTS()` 与 watchlist 状态，
  selector.ts 少 220 行、ts.ts 少 65 行）。要回到三层就回滚到 6.41。

> 历史：tput 曾在"带宽崩塌"用抽签更差（2.68x → 4.22x）而退回粘滞游标；`T=50` 复测后 2.36 → 1.61 才重新开。
> 滞回必须按**主项**算，不按总分：总分含 `5000×pFail`，用 `总分×0.15` 时 250ms 节点的门槛被抬到 210ms。

**回滚**：游标切换后 60 s 内出现失败 → 切回，该节点 30 min 内不再自动选。

**失败阶梯**：`[10s(小池)/60s, 5m, 15m, 20m]`；最后一档从 60 min 降到 20 min ——
恢复的节点不该被关一小时（实测"死亡后恢复"从 44 分钟降到 10 分钟）。

## 6. 冷启动探索（喂第一批样本的唯一入口）

```js
base     = pxShadow ?? 0.05;                  // 环境变量；0 = 关闭
exploreP = base;                             // 只用于站点冷启动；全局探索交给 ③ 的抽样器（σ 驱动）
```

- 只作用于**新建连接**，在途连接不动；已经重试过的连接（`st.retried`）不再试验
- 站点优先：这个域名试过的节点 < 3 时先补站点样本（`hostUntried`）—— 这条在两种模式下都保留
- **不再有全局 watchlist 的 `trial()`**（v6.42 删除）：抽样器的乐观面本来就是
  "样本越少抽得越多"，再叠加一层"挑样本最少的那个"等于把 5% 流量专门送给最差的节点
  （8 种子：100 节点 1.30→1.25、800 节点 1.24→1.22、带宽崩塌 3.07→2.43）。
  `pxShadow` 在新路径上只剩"站点画像补样本"这一个作用。
- 影子连接失败/卡顿 → 该节点 5 min 内不再入选（`freeUntil`）
- 它是"有没有第一批样本"的问题；**之后分多少流量由 ③ 的抽样器决定**，
  两者不再叠加（旧实现里 ② 和 ③ 会同时放大探索）。

|---|---|---|---|---|---|---|---|

## 9. 可解释接口

`GET /<uuid>/proxyip?why=1`

```json
{"colo":"AMS","mode":"tput","cur":"45.147.250.39:443",
 "explain":[
  {"k":"45.147.250.39:443","v":5109,"chosen":true,
   "terms":{"e10mb":5000,"tcp":19,"fail":80,"stall":10,"gate":0},
   "n":132,"bytesDown":734003200,"pFail":0.010,"bps_p90":2097152},
  {"k":"91.215.154.80:443","v":33803,"chosen":false,
   "terms":{"e10mb":33333,"tcp":20,"fail":400,"stall":50,"gate":0},
   "n":9,"bytesDown":1887436,"pFail":0.05,"bps_p90":314572}
 ]}
```

`GET /<uuid>/debug?cl=1`（加 `&do=1` 连 DO 环形一起读）

```json
{"local":[{"t":1762952400,"k":"45.147.250.39:443","ms":78,"dn":524288,"up":8192,"ok":1}],
 "ring":[ ...最近 60 条，跨 isolate... ],
 "now":1762952500000}
```

每条连接一行：`t` 秒级时间戳、`k` 节点 key（直连记 `"direct"`）、`ms` 首字节、`dn/up` 字节、
`ok` 是否成功。落盘走已有的 `/add` 批次（`body.cl`），不新增 KV/DO 请求；
用途是**离线标定**：把 `ms` 与真实体感对一遍，才知道 `JIT_W`、`REAL_W` 该取多少，
以及"节点报的 ttfb 分布"是否与面板上的一致。

## 10. 参数总表

| 参数 | 默认 | 说明 |
|---|---|---|
| `HL` | 6 h | 衰减半衰期 |
| `alphaTcp` | 0.3 | EWMA 系数 |
| `priorTcp/priorTls` | 250 / 60 ms | 冷启动先验 |
| `FAIL` | 5000 ms | 固定的失败当量，只在 `FAIL_SCALE=0` 时生效 |
| `FAIL_SCALE` | 1.6 | 失败代价按目标流量定价：`failMs = clamp(1.6 × (L + 传输时间), 400, 20000)` |
| `STALL` | 2500 ms | 卡顿当量 |
| `tlsGain` | 1.2 | 握手权重 |
| `lossGain/lossSlack` | 2 / 30 ms | 重传判定 |
| `confLat` | 1-e^(-latN/4) | 延迟置信度（latN = 探活 + 成功连接） |
| `REAL_W / PROBE_W` | 8 / 2 | ttfb 与探活各占几份权重 |
| `JIT_W` | 0.5 | 抖动（ttfb 标准差）进分数的系数 |
| `confB` 门槛 | nEff≥3 且 3 MiB 且 ≤24 h | 吞吐置信度准入 |
| `priorBps` | 2 MB/s | 无样本时的 E10MB≈5 s |
| `LAT_BYTES` | 160 KB | 延迟模式的"典型请求" |
| `H_lat / H_tput` | 20 ms / 25% | 滞回（只约束游标记账） |
| `DWELL` | 10 min / 20 min | 最小驻留（lat / tput） |
| `budget` | 3 /h | 切换预算 |
| `pShadow` | 5% | 冷启动探索比例（`exploreP` 只按它算） |
| `TS_K / TS_K_LAT / TS_K_SMALL / TS_K_BIG_MIN / TS_EXTRA` | 64 / 32 / 32 / 1200 / 64 | 抽样池宽度（大池按模式分档）/ 未测节点补入上限 |
| `TS_K_SMALL / TS_K_BIG_MIN` | 32 / 1200 | 池子 <1200 时分数榜取前 32（300~800 池集中采样），≥1200 取前 64 |
| `TS_BETA / TS_SD_MIN / TS_BAND` | 0.8 / 20 ms / 300 ms | 乐观面系数 / 抽样噪声下限 / 剪枝带宽 |
| `TS_HIER` | 1 | 传输时间用"节点自己的测量 + 池内最快兜底"（纯 Thompson 的开关 `TS_PURE` 随旧路径在 v6.42 删除） |
| `CUSUM_K / CUSUM_H / CUSUM_FREEZE` | 30 ms / 300 ms / 60 s | 延迟变点容差 / 报警阈值 / 报警后冻结时长 |
| `cusB` 阈值 | 1.2 | 吞吐变点累积量（log2 倍数） |
| `SZ_I / SZ_S / SZ_B` | 64 KB / 1 MiB / 16 MiB | `?sz=i` / `?sz=s` / `?sz=b` 的目标流量 |
| `rollback` | 60 s → 冻 30 min | 回滚 |

## 11. 验收用例

| 场景 | 期望 |
|---|---|
| 全新节点（n=0） | 排在中位数附近，不抢第一 |

## 16. 「最优命中率」的口径（仿真里的 oracle 与我们的目标函数不同）

`tools/sim-select.mjs` 的 oracle 是 `trueCost(n) = (rtt + bytes/bw) / (1 − pFail)`：
它把失败**线性**折算成时间。我们的代价函数把一次失败记 **5000 ms**（连接的体感代价：
重连 + 应用层超时）。两者在"高失败率但低延迟"的诱饵节点上会给出不同结论：

- 20 节点池里的 `n2`（tcp 30、失败率 8%、bw 8MB/s）：oracle 期望 112 ms；我们算 503 ms；`n0` 是 150 ms。
- 所以算法从不选 `n2`，命中率显示 0%，但**它的选择在"5000 ms/次失败"的口径下是对的**；
  相对这个 oracle 的下限就是 1.12x —— 这也是"20 节点 1.33x"里那 0.2 的主要来源。

要看算法的真实水平，应该看 `±2%` 列（1.33x 的池子里 0%/0% 说明确实没有第二个同样好的节点）
与大池的命中率（2000 节点 73%）。**结论口径不变**：不承诺"每次最优"，承诺
"不选黑名单/冻结、失败退避、`checkTarget` 复验、大池 7 成命中、p95 ≈1.5–2.0x"。

## 19. v6.39 修订：失败代价按流量定价 + 层次化传输先验

两个改动都来自同一类观察：**「最优」是相对于目标流量 S 的**。同一个池子里，64 KB 交互的最优是低延迟节点，16 MB 批量的最优是大带宽节点（`crossPool` 里 A=60ms/2MB/s、D=300ms/40MB/s）；而原来的目标函数对两者的排序几乎一样。

### 19.1 失败代价随 S 缩放（`FAIL_SCALE`）

`failMs = clamp(FAIL_SCALE × (latencyMs + 传输时间), 400, 20000)`，两条 score 公式用它替代固定的 `FAIL=5000`；抽样层的 `sdF` 也跟着换成 `p.failMs`。

理由：一次失败丢的是「重试的代价」，量级是 base 的 1~2 倍，而不是常数。64 KB 交互失败只丢一个 RTT（~150 ms），按 5000 ms 计等于把「快但偶尔失败」的节点永久判死；16 MB 批量失败要重传十几秒，5000 ms 又太便宜。仿真里 oracle 用 `cost/(1−p)` 线性折算，这一项差异直接造成「20 节点命中率 0%、正常 DE 1.47x」。

`FAIL_SCALE=0` 回退到固定 5000 ms，便于 A/B。

### 19.2 传输时间用「节点自己的测量 + 池内最快兜底」（`TS_HIER`）

抽样层原来直接用 `score` 里的传输项，而 `score` 对没有带宽证据的节点套全局先验 `priorBps=2 MB/s`：16 MB 场景里 40 MB/s 的节点被算成 8 秒，永远排在「已经测出 10 MB/s」的节点后面（最优命中率 7%）。

现在抽样层的均值改成：

```ts
const tms  = mode === "tput" ? p.e10Ms : p.xferMs;                 // score 里的传输项（confB 加权过）
const tRaw = p.capBps > 0 ? sz / max(8KB, p.capBps) * 1000        // 有测量：直接按测量
                          : sz / capMax * 1000;                   // 没测量：按池内最快（乐观先验）
const mean = p.score - tms + tRaw;                                // 只替换传输项，其余照旧
```

`capMax` 是候选表前 kMax 名里最大的 `capBps`（下限 `priorBps`）。`confB` 只留在 `sdB`（不确定性）里，不再决定均值 —— 均值要么是测量、要么是乐观先验，不允许出现「测了反而更差」的中间态。

同时修了一个锁死：**低样本臂豁免剪枝**（`low.push(p.confB < 0.05 || p.latN < 3)`），否则「没测过 → 先验慢 → 被剪掉 → 永远没测过」。

### 19.3 被否掉的：纯 Thompson（`TS_PURE`）

按 σ 抽样（不再减 βσ、噪声用 σ）在跨模式场景有效（16 MB 1.16→1.07、带宽崩塌 1.39→1.15），但在大池灾难性退化：300 节点 1.33x、800 节点 1.51x、**2000 节点 1.74x** —— σ 驱动的探索在 2000 池里把 30~40% 流量送给慢节点。保留 UCB 形式（减 βσ + 固定 20 ms 抖动），只在先验上做文章。该开关随旧路径在 v6.42 一并删除。

### 19.4 仿真口径修正（所有历史数字相对它都会变）

`tools/sim-select.mjs` 的吞吐样本原来用整个 `dur`（含首字节等待）当分母，系统性低估高延迟节点带宽（D 的 40 MB/s 被算成 21 MB/s），16 MB 场景在口径上就不可能选对它。现改成 `tx = max(dur*0.4, dur - stall - rtt)`，与生产一致（`Connection` 的采样窗口从首字节之后才开始）。**修口径后所有历史数字都会变，跨轮对比必须用同一份 sim 重跑。**

## 20 v6.41 修订：大池（2k~3k）的探活判死与抽样池分模式

真实池子规模是 2000~3000 个候选，这一版针对"每次请求能否落到最优"做了两件事。

### 20.1 探活判死（`deadEnd`）

`pickThom` 里对每个候选先看它有没有流量样本：`p.n < 1`（`n = okW + failW`）。如果一条流量样本都没有、而它的 `latencyMs`（此时几乎完全由探活决定）已经超过 `latMin * TS_CUT_R + TS_CUT_MS`（默认 1.5 倍 + 40ms），就给它记 `+1e7` 的惩罚——**不再花流量去试一个探活就能判死的节点**。

`latMin` 取排行榜第一名的落盘延迟（`S.nstat.get(list[0].k).pSum`），O(1)，不额外遍历。

只对 `lat` 模式生效：吞吐模式的成本由带宽决定，延迟不构成判据（早期在 tput 上也开，带宽崩塌从 1.17x 退化到 1.21x）。

### 20.2 抽样池宽度按模式分

`kMax = nPool >= TS_K_BIG_MIN（1200） ? (tput ? TS_K=64 : TS_K_LAT=32) : TS_K_SMALL=32`。

2000~3000 池的实测（4 种子）：lat 模式 32 名比 64 名好（1.16→1.14 / 1.17→1.14，命中 60%→64% / 58%→64%），因为前 64 名里有一半的节点成本差在测量噪声以内，摊薄了采样；tput 模式必须留 64，收窄会让带宽崩塌后的恢复变慢。

### 20.4 为什么"每次都是最优"做不到

- 3000 池、8h、约 2.9 万次请求 ≈ **每个候选 10 条样本**；σ≈20ms 时标准误 ≈ 6ms，而池内前几名的成本差经常 <5ms —— 在噪声以内，换谁都对。
- 命中率 64% 的同时代价只有 1.14x（p95 1.4x、超过 1.5x 的请求只占 4%），说明"选错"的那 36% 落在**成本几乎相同**的节点上，不是选到了差节点。
- 想逼近 100% 只有两条路：每候选更多流量（20/s 以上）、或把候选池缩到 800 以内（线上 `ALIVE_MAX=800`，实测 1.12x / 70%）。
