## 1. 分层职责

| 层 | 职责 | 状态归属 | 生命周期 |
|---|---|---|---|
| 接入 | 认证、协议解析、模式解析 | 无 | 单请求 |
| 路由 | direct / node / v6 决策 | `st.via` | 单连接 |

| 观测 | 吞吐/延迟/卡顿画像 | 内存 → DO/KV | 持久 |
| 控制面 | 面板、订阅、诊断 | 无 | 单请求 |
| 调度 | 重建池、探测、落盘、续用 | cron isolate | 30 min |

## 3. 三条关键数据流

### 3.1 一条 WS 连接

```
请求 → 认证 → 解析首包 → 选通道
  ├ direct: dial(target)
  ├ node  : dial(CUR) 且 st.node = "h:p"
  └ v6    : dial(v6)
→ pipeUp/pipeBack 双向
     · 每 256 KB：flushStat(增量, 采样)
     · 每 1 s 窗口：产出一个吞吐样本        [已设计]
     · 客户端背压：bufferedAmount > LIMIT 时暂停读，累计 stallMs
→ 关闭：flushStat(closing=true) → scheduleFlush → PEND → DO
```

### 3.2 一次 cron（30 min）

```
pxGet(env)                      读 seed（30 min 缓存）
ensurePool                      池子 24 h 才重建
probe 12 个新候选               发现新 alive
recheck CUR + top3              黑名单（失败即拉黑）
probe 其余 alive（≤12）          只刷新延迟，不拉黑        [已上线]
maybeUpgrade                    15% 优势才升级             [已上线]
schedSwitch                     pxSchedH=6，前二名轮换     [已上线]
seedWrite                       1 次 KV 写
pendFlush(force)                DO 落一次
usageSnap + restore             续接用量
```

### 3.3 一次面板请求

```
GET /<uuid>/proxyip          → 读 seed + 本 isolate NSTAT
GET /<uuid>/proxyip?why=1    → 每节点打分分解              [已设计]
GET /<uuid>/cl|sb|ty         → 生成订阅（含分组）          [已设计]
GET /<uuid>/stats            → 用量 + 节点表
```

## 5. 选择与观测（本轮的重新设计）

### 5.1 选择的输入

| 量 | 全节点可得 | 进评分 | 说明 |
|---|---|---|---|
| TCP 建连 | ✓（探活） | ✓ | 距离 |
| TLS 往返 | ✓（探活） | ✓ | 丢包信号 |
| 失败率 | ✓（衰减权重） | ✓ | 半衰期 6 h |
| 卡顿率 | 仅用过的 | 部分 | 体感 |
| 吞吐 | **仅用过的** | 仅 tput 模式 | 靠影子采样覆盖 |

### 5.2 死锁怎么破

```
旧: 用过的节点有 bps → 分更高 → 更被选中 → 冷节点永无 bps
新: 影子流量(5~10%)强制给冷节点喂真实连接 → 3 个样本即"已测"
```
**死锁由采样机制打破，不是由公式打破。**

### 5.3 两种排名

```
lat :  v = tcp + tls*1.2 + loss + pFail*8000 + pStall*2500
tput:  E10MB = 10MB / bps_p90 * 1000 + pFail*8000
```
单位统一成毫秒当量，任何一个分数都能解释成"多花多少毫秒"。

### 5.4 切换的闸门

```
滞回    lat 20ms / tput 15%
驻留    10 min
预算    3 次/小时/游标
回滚    切换后 60s 内劣化 → 立刻切回，30 min 内不再自动选它
```

## 7. 不变量

1. 数据面绝不 `await` 持久化 —— 一律 `ctx.waitUntil`
2. 统计/观测失败不得影响连接
3. 直连字节不进节点桶
4. 上行不进主列、不进评分
5. `未用` ≠ `0 KB/s`
6. 选择状态（CUR/ALIVE/NSTAT）不跨 isolate；计量状态必须跨 isolate
7. 评分只用"全节点可得"的量；吞吐靠采样覆盖，不靠公式偏袒

## 9. 落地顺序

```
P0  px:seed 分桶 + ensureAlive 只读本桶      ← 修现存错误信号

```

# v6 实施记录（已上线）

## 已落地

| 项 | 说明 |
|---|---|
| `px:seed` 按机房分桶 | `byColo[COLO]`；`*` 桶只存候选名单（无统计），供未跑过 cron 的机房冷启动 |
| 冷启动只继承本机房 | 本桶为空时借用 `*` 或其他机房的**名字**，延迟一律用先验 250 ms，杜绝跨机房污染 |
| 三段计时 | `probeProxy` 返回 `tcp`（建连）与 `tls`（首个证书字节），cron 写进 `nsOk` |
| 1 秒窗口采样 | `onBytes` 从首字节起算，1 s 或 256 KB 切窗；<200 ms / <32 KB 丢弃；每连接 5 s 最多 1 个样本 |
| 评分 v2 | 毫秒当量 + 6 h 衰减 + Beta 先验 + 置信度收缩 + 单向 gate |
| 双游标 | `CURS.{lat,tput}`，独立滞回/驻留/预算/回滚 |
| 影子流量 | `pxShadow`（默认 0.1，双游标时各半），只作用于新连接 |
| 订阅分组 | 一份 YAML 内 `🚀 吞吐优先` / `⚡ 速率优先` / `🌍 地区` / `🎯 手动`，节点带 `-T/-L` 后缀 |
| 黑名单 | 指数退避 60s → 5min → 15min → 1h，成功后清零 |
| `?why=1` | 每节点打分逐项分解 |
| 面板 | 本机房、双游标、三通道占比、`未用` 三态 |

## 新增绑定（可选，有默认值）

```

```

## 本轮踩到并修掉的三个坑

1. **`seedWrite(listOnly)` 用名字覆盖统计** —— `?refresh=1` 在服务 isolate 里跑时把本机房桶写成名单，
   延迟全丢。改为按 `COLO` 是否存在决定写全量还是名单。
2. **空表落盘** —— 探测 12 个候选全挂时写了个空桶，把好数据盖掉。改为空表只刷全局字段。
3. **空结果缓存 30 分钟** —— 新机房首个请求读到空表后，接下来半小时都拿不到节点。改为空表只缓存 1 分钟。
