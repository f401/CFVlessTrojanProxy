# 本地验证（不发版也能改代码）

目标：把「改一行 → 推 CF → 等 6 秒 → 拉 /health」的循环压到本地，部署只在必要时发生。

## 一条命令

```bash
node tools/preflight.mjs          # 全部门禁 + 本地路由模拟，29 秒左右，不发版
node tools/preflight.mjs --fast   # 跳过 sim_v3 与 golden（改注释/文案时）
node tools/preflight.mjs --deploy # 全绿后顺手部署（等于手动跑 .tmp-sim/deploy-746.mjs）
```

包含：tsc → check-arch → bundle → mk_test → test_v3 → smoke_v3 → test_score → sim_v3 → golden → obf/pre → obf/obf_mid → check-obf → simrun。

## 本地跑真实请求

```bash
node tools/simrun.mjs                       # 标准套件（9 个路径）
node tools/simrun.mjs /health               # 单个路径
node tools/simrun.mjs "/<uuid>/debug?vt=example.com"
```

`tools/simrun.mjs` 用 `test/_bundle.mjs` 直接 `fetch()`，KV 是内存 Map，UUID 用
`7c53c12a-88b1-4fda-b6e7-4da62e47a4e1`（可用 `SIM_UUID` / `SIM_HOST` / `SIM_KEY` 覆盖）。
能验证：路由匹配、状态码、序列化字段、订阅生成（clash 的 `proxies:` 条数、sing-box 出站）、判定逻辑。

| 本地能验 | 本地验不了（必须真机/真 CF） |
| --- | --- |
| 路由、状态码、JSON 字段、面板与订阅文本 | DO 的 sqlite 迁移、跨 isolate KV 传播、cron 30 分钟一轮 |
| 评分/阈值/判定分支（单测 + 场景仿真） | CF CPU 时间（1102）、子请求上限、内存 128MB |
| 混淆后关键字残留、包体积 | 真实出口到目标的 TLS/HTTP 行为与机房差异 |
| 订阅里 proxies 数量与字段 | 客户端（mihomo）真的能不能连、url-test 选哪个边缘 |

## 部署时机（默认不发版）

只有这三种情况值得推 CF：

1. 用户明确要求上线（「部署」「看看线上」）；
2. 改动落在上表右列（运行时限制、DO/KV 语义、真实网络）；
3. 要发版本号（`src/core/util.ts` 的 `VERSION`）对外可见。

其余情况：本地 preflight 全绿 + commit 即可，多个改动攒成一次部署。

## 发版链（需要时）

```
node tools/preflight.mjs --deploy
# 或手动：tsc → check-arch → bundle → mk_test → 四段测试 → golden
#        → obf/pre.js → obf/obf_mid.js → node .tmp-sim/deploy-746.mjs → 拉 /health
```

`obf/obf_mid.js` 吃的是 `obf/pre.js` 的产物（`_worker_v3.pre.js`），两个都要跑；
漏跑 `pre.js` 会「部署成功但版本号没变」。
