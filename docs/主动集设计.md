# 主动集（Active Set）设计 · Phase 1

> 一句话：把"800 个节点抢 5% 流量"改成"64 个活跃节点吃全部流量 + 每小时轮换 8 个"。

## 0. 为什么是它

实测：800 节点池里，2 小时后拿到 ≥2 个样本的节点只有 **4%**；400 节点是 9%。
5% 的探索摊到 N 个节点，等于没探索。加节点只提高了"池子里最好的那个"的上限，
选路精度并不会跟着涨（400→1600 节点都是 1.26x）。

主动集把"池子大小 → 采样覆盖率 → 选路精度"这条耦合切断。

## 1. 不变量

- `active ⊆ alive`；
- `|active.lat| ≤ 64`、`|active.tput| ≤ 16`（吞吐样本贵，活跃集小）；
- 每条连接只在 active 里选；
- 每小时探索次数 ≤ 60（lat）/ 6（tput）；
- 任何节点在 active 里连续待满 8 小时必须让位（除非一直排前 25%）。

## 2. 数据结构

```ts
// core/state.ts，AppState 新增
active = { lat: new Set<string>(), tput: new Set<string>() };
activeAt = new Map<string, number>();      // key -> 最后一次提拔时间
trialWin = { h: -1, lat: 0, tput: 0 };     // 本小时已用的探索次数
failWin = { h: -1, n: 0 };                 // 本小时全局失败次数
```

内存：64 + 16 个字符串 + 2 个 Map ≈ 几 KB，可忽略。

## 3. 生命周期

### 3.1 提拔（cron，每 30 分钟）

```
候选 = alive − active，usable，探活 ms ≤ 250
排序 v = 探活 ms + 200/√(样本数+1)
取前 8（lat）/ 前 2（tput）
```

- 有空位直接进；满了就挤掉"排名后 25% 且停留最久"的那个；
- 提拔只改成员，不动统计（统计一直在 `S.nstat` 里）。

### 3.2 降级

| 条件 | 动作 |
|---|---|
| 连续 6 小时排 active 后 25% | 移出 active，回储备池 |
| `usable=false` 超过 30 分钟 | 移出（冷却/冻结的节点不该占名额） |
| 连续失败到熔断 | 移出，等冷却结束再参与提拔 |

### 3.3 淘汰（alive 超过 800 时）

优先删"不在 active、探活最慢、且 6 小时没有流量"的；现有淘汰逻辑已经按
"不在当前池 → 更慢"排序，只需要把"是否 active"作为第一优先级。

## 4. 选路

```ts
pickByScore(mode) {
  const list = candsFor(mode, S.active[mode]);   // 只排 64 个
  ... 前 12 名 softmax（lat T=20 / tput T=50） ...
}
```

`candsFor(mode, pool?)` 增加可选参数，缓存键变成 `${mode}:${pool ? "a" : "all"}`：

- `lat:active` / `tput:active` —— 每条连接用；
- `lat:all` / `tput:all` —— cron 排名、提拔、面板用。

成本：排序 64 个 ≈ 50µs（现在 800 个是 661µs），每 20 秒一次。

## 5. 探索预算

`trial()` 只从 active 里选，并且受每小时配额限制：

| 模式 | 每小时探索 | 每次成本 | 每小时流量 |
|---|---|---|---|
| lat | 60 次 | ~0.2 MB | ~12 MB |
| tput | 6 次 | 10 MB | 60 MB |

配额用完 → 不再 trial，纯 softmax；跨小时自动重置（用 `NOW/3600e3` 做窗口键）。

相比现在"5% 摊给 800 个"，这套是 **O(1)**：池子涨到 1600，探索成本不变。

## 6. 冷启动与持久化

- seed 里给每条记录加 `a: 1` 标记（lat/tput 活跃）；
- 冷启动：从 seed 恢复 active 成员和统计；前 3 轮 cron 每轮提拔 16 个，快速填满；
- `SEED_MAX=800` 不变；active 标记只有 80 个，体积可忽略。

## 7. 失败预算

- 全局 30 次/小时；超了 → active 临时收缩到前 16、暂停提拔，下一个小时恢复；
- 单节点阶梯（10s/5m/15m/20m）不变 —— 实测 Markov 故障下只有 0.7% 请求打到死节点，这套是有效的。

## 9. 验收标准

单测：提拔（空位/挤人/候选空）、降级（6 小时/不可用）、配额（跨小时重置）、缓存键（active/all 不串）。

仿真（35 场景 + 真实画像 9 个）：

| 指标 | 现在 | 目标 |
|---|---|---|
| lat 常规 | 1.38–1.43x | ≤ 1.35x |
| tput 真实画像 | 1.61x | ≤ 1.55x |
| 有样本覆盖率（800 池） | 4% | 100%（64/64） |
| `pick` | 2.8µs | ≤ 5µs |
| `candsFor` | 661µs | ≤ 80µs |

## 10. 风险与回滚

- **活跃集选错**（把好节点挡在外面）：靠每小时 8 个轮换 + 6 小时强制让位兜底；
- **tput 活跃集只有 16 个**：可能错过"突然变快"的节点；靠 seed 带宽和探活兜底，必要时提到 24；
- **回滚**：`ACTIVE_LAT=800`、`ACTIVE_TPUT=800` 就退化成当前行为（只多一个 Set 判断）。

## 11. 分阶段

1. **Phase 1（本文）**：活跃集 + 配额 + 失败预算；
2. Phase 2：估计器拆分（TTFB 双向、吞吐 1h 窗口、可用性滑动窗口）；
3. Phase 3：策略层显式化（每类权重 + 面板展示"当前策略"）。
