# 命名约定

这份文件是 [tools/check-names.mjs](../tools/check-names.mjs) 的说明书，也是它的判据来源之一：
门禁会读这个文件，**ALLOW 表里每一个被放行的短名都必须在这里有一条解释，漏写就红**。

为什么要有这份东西：这个仓库里同一个量曾在三处用三种写法（7.154 的 `VT_TTL` 分裂成两份、7.226 的
`PX_TTL` 与内联 `6 * 3600e3`、7.188 的十处裸 `2500` 与语义完全不同的 `SC.STALL`）。名字一样而含义
不同的两个量，比名字难看的代码危险得多 —— 编译器不会替你看出来。

## 1. 成员名必须能读出含义

`class` / `interface` / `type X = { … }` 的成员名长度 **≤ 2** 一律不合格，除非它在下面的 ALLOW 表里。

改名的两端必须在同一批里一起改，并且要用「读端跑一遍行为」的断言兜底 —— 7.253 就是自己把
`PickState.sz` 改成了 `bytes`、而 `Connection` 那边的同义字段改成了 `targetBytes`，`tsc` 不报
（可选字段），运行时读 `undefined` 恒 0；抓住它的是一条既有断言「pick 会把目标流量传进打分」。

## 2. 单位写进名字

| 后缀 | 含义 | 例子 |
|---|---|---|
| `Ms` | 毫秒时长 | `firstByteMs`、`ageMs`、`BATCH_GAP_MS` |
| `At` | 时间戳（`EpochMs`） | `updatedAt`、`lastBatchAt`、`quotaAt` |
| `Bps` | 每秒字节 | `kiloBytesPerSec`、`capBps` |
| `Count` / `Bytes` | 个数 / 字节数 | `samples`、`targetBytes` |

反例（历史）：`SC.STALL = 2500` 与「建连超时的 2500」数字相同、语义完全不同，后来者拿它当超时上限，
代码不会报错、只会静默换语义 —— 现在建连上限叫 `CONNECT_MS`。

## 3. 闭集合用枚举

只允许 `src/core/enums.ts` 里的 `St`（判定状态：`Unknown` / `Reachable` / `Blocked` / `Dead`）与
`Mode`（`Throughput` / `Latency`）。判定状态在 7.162 与 7.164 各被「裸数字 3 当成 2」丢过一次维度，
现在任何新代码都写 `St.Dead` 而不是 `3`。

## 4. 有界表用 `BoundedMap`

「先清过期、再按时间收到低水位」这条规则只允许存在于 `src/core/table.ts` 的 `BoundedMap`（它继承
`Map`，所以消费方的 `get/set/size/entries` 都不用改）。过去它在四处各写一遍，7.250 的
「上限判在插入之前、表稳定停在 max+1」就是其中一处。

有没有例外？有，而且必须写明理由：`src/route/relay-health.ts` 的 `drop()` 要**跳过 `dead > 0` 的行**
（硬结论得留着）并同步第三张表 `pending`，通用淘汰规则表达不了这种偏好，所以它保留自己的实现 ——
测试里锁住了这条偏好，见第 255 组。

## 5. 语义别名放在 `src/core/types.ts`

`EpochMs` / `DurationMs` / `KiloBytesPerSec` / `SampleCount` / `RelayIp` / `HostName` / `NodeKey` /
`ChanToken`。这里用别名而不是 branded type，是因为这些量要穿过 JSON / KV / DO 边界，branding 得在每个
边界上断言，收益不抵噪音。

## ALLOW：允许的短名

每一条都要回答「为什么短名字这里是对的」。新增一条，就必须在这里补一行，否则门禁红。

| 短名 | 含义 | 为什么允许 |
|---|---|---|
| `id` | 用户 / 实例标识 | 就叫 `id`，没有更短更清楚的写法 |
| `ip` | 中继地址 | 线协议与面板里都写作 `ip` |
| `cf` | Cloudflare 托管标记 | `cf` 是 Cloudflare 的公认缩写 |
| `ok` | 布尔成功标记 | 判定表里除 `St.Reachable` 之外只有它 |
| `up` | 上行字节数 | 与 `down` 成对，单位写在类型注释里 |
| `ms` | 毫秒数 | 单位已经写进名字，等价于 `millis` |
| `vt` | 判定事实表（线协议键） | 五类事实表的跨 isolate 键，改名要迁移 DO 存储 |
| `hl` | 中继存活事实表（同上） | 同上 |
| `eg` | 出口族事实表（同上） | 同上 |
| `ps` | 站点成功事实表（同上） | 同上 |
| `dns` | DNS 事实表（同上） | 同上 |
| `cl` | 连接样本事实表（同上） | 同上 |

后面六个是**线协议/存储键**：它们在 `src/store/factout.ts`、`src/store/meter*.ts`、
`src/route/verdictsync.ts` 里同时是 JSON 字段名与 DO 存储键，改名的代价是「新名为主 + 读端接受旧名」
的迁移，属于单独的批次，而不是顺手改。

## 6. 棘轮

`tools/naming-baseline.json` 的 `{ "opaque": N }` 是上限：实测**多于**基线 → 红；**少于**基线 → 也红
（提示把基线下调）。只许往下走，不许回弹。当前基线在文件里，不在本文档里复制一份 —— 复制出来的第二份
数字迟早会与真相不一致。

## 7. 线协议键（登记例外）

下面这些键同时是 **JSON 字段名**与 **DO / KV 存储键**（`src/store/factout.ts`、`src/store/meter*.ts`、
`src/route/verdictsync.ts`、五张 `*facts.ts` 的线格式、`src/core/facts.ts` 的行类型）。改名意味着
「新名为主 + 读端接受旧名」地迁移存量数据（`px:pool`、`px:seed`、DO 的 `vt`/`hl`/`blk2`/`dns` 分片），
那是单独的一次迁移，不是顺手改。

它们的含义由**这张表**定义，代码里不再重复解释；新增短名必须先进这张表与 `tools/check-names.mjs`
的 `ALLOW`，两处缺一处门禁就红。除此之外，新写的类字段 / 接口成员不允许出现 ≤2 字符的名字。

| 短名 | 含义 | 出现在哪 |
|---|---|---|
| `at` | 观测时刻（毫秒时间戳） | 五类事实表、判定表、快照行 |
| `n` | 次数或计数（批数、样本数） | 事实表、`cl` 聚合、错误环 |
| `t` | 时间戳或到期时间 | `hl`/`vt`/`blk2` 线格式、`S.rankCache` |
| `s` | 状态或结构体（`state` / `snap`） | `vt` 线格式、计量 DO 的 `s` 表 |
| `c` | 计数或通道（`counter` / `chan`） | 计量 DO 的 `c`、`PrefRow.c` |
| `k` | 键（`target\|chan`、`host\|relay`） | `vt`/`ps` 线格式、`factout` |
| `i` | 标识（中继 IP、条目 id） | `hl`/`ps`/`eg` 线格式 |
| `j` | JSON 载荷（`/add` 的结构体） | `commitfact` 的 `FactOut.j` |
| `v` | 值（族的观测值） | `eg`/`dns` 线格式 |
| `h` | 主机键 | `dns` 线格式 |
| `f` | 族或因子（`eg` 的出口族） | `eg` 线格式 |
| `q` | 质量（成功率） | `ps` 线格式 |
| `o` / `b` / `d` | 好 / 坏 / 死 三计数 | `hl` 与 `blk2` 线格式 |
| `e` | 错误数组（`err`） | 计量 DO 的 `e` 表 |
| `g` | 计数器文档 / 分代 | 计量 DO 存储键 |
| `v6` | IPv6 观测计数 | `dns` 线格式 |
| `fs` | 存储格式代号 | 计量 DO 分片代号 |
