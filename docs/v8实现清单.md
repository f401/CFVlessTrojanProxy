# v8 实现清单

> 这份文档只做一件事：把 `docs/v8.md` 里**被实验证明过**的硬规则抽成一页可勾选的清单。
> 每条都带「数字 + 出处」；没有出处的不许加进来。实现时逐条打勾，评审时逐条核对。

## A. 事实层（DO）

- [ ] 表结构：`facts(kind TEXT, k TEXT, at INTEGER, j TEXT, PRIMARY KEY(kind,k)) WITHOUT ROWID` + `idx_facts_at(kind,at)`（§3.3）
- [ ] 唯一写入口：`INSERT … ON CONFLICT(kind,k) DO UPDATE SET at=excluded.at, j=excluded.j WHERE excluded.at > facts.at`（**严格 `>`**，相同 `at` 也忽略，防两 isolate 乒乓；§3.3）
- [ ] 五类事实与 TTL：`dns` 24h / `eg` 6h / `ps` 45min / `blk` 90min / `dead` 30min（§3.1、§5.1；`blk` 与 `ps` 寿命不同是故意的）
- [ ] 容量上限：`dns 512 / eg 512 / ps 512 / blk 1024 / dead 256`；**淘汰在写入之前跑**，只删本 kind、按 `at` 升序（§3.3、§3.3）
- [ ] 读取：`GET /meter/facts?s=<kind>&since=<ts>` **按 kind 分片**；单 kind 一次 <8KB（整库最坏 ~250KB，不能一次全拉；§3.3）
- [ ] 写入：**isolate 结束即冲写**（一次 ≤3 行），不设 16 条门槛（§3.4 D13：3 连 isolate 永远攒不满，等于一条不写）；≤64 行/次；>20 万连接/天开抽样，`k = ceil(连接数/30万)`，丢弃计入 `psDrop`（§3.4）
- [ ] `SQLITE_FULL` 捕获后降级不抛错；`since` 只在成功应用后前移（§3.3）
- [ ] facts 写失败只降级事实层：连接照常返回、计量表单独建表并优先保障；`/health` 暴露 `factFull`（§14.3 D19）

## B. 判定（写入闸门）

- [ ] 只有 `commitFact` 一个写入口，规则顺序固定：节流 → 回显 `eg` → 中继坏 `dead` → `429` 退避 → 站点级 → `blk` → 完整响应 `ps(ok)` → 零字节（§3.2）
- [ ] `tiny = down > 0 && down ≤ 2048 && down < 0.2 × bigTypical[host]`（**不是 ≤64**：封锁页已是 737B HTML；§4）
- [ ] `blk` 需要四件同时成立：`tiny` + 同 120s 窗口有 ≥20KB 对照 + **三个批次**（间隔 ≥60s）+ **每批 ≥3 次**；三批不是两批（§3.2：假阳性 0.25% → 0.01%）；写入后只降权 ×6（§15.2）
- [ ] `blk` 键 `${host}|${relayIP}`；**直连腿永不可写**（CF 边缘身份不可归属）；全通道 4xx / 429 永不写（§4）
- [ ] `ps` 允许吃 B 级负样本（单批 `tiny` + 同窗口 ≥20KB 对照），但只做「机会归一化的失败计数」；负样本步长与正样本同阶（§5.1 D14）
- [ ] 同质化检测：候选 p 估计 max/min < 1.5 时视为同质，改走轮换 + 康复通道（§5.1）；轮换顺序按 `ps` 降序（加 `it` 偏移），不按字典序（§14.3 D18）
- [ ] 成功判据是 `down > 64`（拿到完整响应），**不是 2xx**（`api.github.com` 415+1277B 是正常业务；§15 D4）
- [ ] `tiny` 响应**不写 `ps(ok=0)`**（`example.com` 932B 会误伤），只加计数（§3.2）

## C. 选路

- [ ] 代价：`transport / max(0.25, p)`；`tput = ttfb + 512KB / max(32KB/s, cap × 64KB/s)`、`lat = ttfb`（§7、§5.1）
- [ ] `p = (q_ps / 255) × 0.6 + prior × 0.4`，`prior = eg==4 ? 0.95 : 0.5`（§5.1、§4）
- [ ] 排序链：`dead 排除 → blk 只乘 6 → 代价 → 探索`；**`dead` 是唯一硬排除，`blk` 永不排除候选**（§15.1 I1/I3）
- [ ] 自愈：某 host 的活跃 `blk` 行 ≥ max(3, 75% 候选) 时判为站点级 → 清空 + 该 host 静默 30 分钟；**静默到期必须恢复写入**（期内 0 行、到期 >0 行，A12 两侧都断言；§15.6）
- [ ] `leastBad()` 的**第一顺位必须是直连**，其次是「历史上有过整页」的中继；永不返回空（§15.7 S5）
- [ ] 探索：8% 请求随机（§8 天花板分解）；**康复通道**：每 20 条请求 1 条走「分数最低但历史上有整页」的中继（§3.2，否则被误判的节点永远回不来）
- [ ] **承诺只写成条件式**：≥1 条可用非 CF 出口（`eg=4` 且未被站点拒）→ 92–96%；只有被拒/v6 出口 → ≤14%（§8）
- [ ] 池子里 `eg=4` 的条数是一等预算项（§5.3）：没有好出口时排序再好也只有 14%；**目标 2 条**（0→1 条值 82 点，1→2 条只值 0.9 点，2 条是冗余而非收益，§8）
- [ ] `ps` 窗口：初值 8、上限 32；连续 3 次成功把 n 重置为 4（§5.4）

## D. 预算与并发

- [ ] 单轮 48 子请求：准入 32–40 / 审计 6–8 / 退款 4 / 入口 0–4（§8）
- [ ] **`connect()` 全局 6 个**，探测按**波次**限流：一波用户连接最多 2 次探测（§6：40 并发 p95 675 → 250ms）
- [ ] `probeWave` 也要约束 `cold+empty` 的后台回显（§6）
- [ ] 复检节奏：每轮 cron 复检 **K=4** 条「最久没看」的中继（128 次/天 = 额度 0.13%）；`believed-good < 2` 超 15 分钟报警并插一轮「找新出口」（§6）
- [ ] `alive` 目标 **16 条**（12 条是下限）：8 条池子有 28.5% 的时间缺第二条好出口，**探测频率买不来供给**（§6）
- [ ] 补货：稳态每轮 3 条新候选 + 1 条复检；`believed-good < 2` 时把 2/3 预算给「`eg` 未知」新候选（§3.4）；新候选结果立刻写 DO
- [ ] 源健康度 `srcRank` 是必需品（6 个源每次运行都有 1–3 个失败，候选量在 342–1065 间跳；§3.4）
- [ ] `readFacts` 四条契约：全有或全无 / 只在冷 isolate 第 1 条连接阻塞 / 每 isolate 10 分钟最多 1 次读（失败 60s 内不重试）/ 陈旧 <1h 仍用并标 `stale`（§3.1）
- [ ] 并发读 **single-flight**（同 isolate 共享同一个 Promise；§6）
- [ ] `connect()` 一律 `withTimeout(2500)`，超时后**关闭迟到的 socket**（7.86 的泄漏教训；§12）

## E. 冷启动

- [ ] 三档：warm 正常 / cold+facts **最多阻塞 200ms** / cold+empty 不阻塞、后台补 1 条回显（§7、§7）
- [ ] colo 缓存 TTL **120s**（60s 在低流量下命中率只有一半；§7）
- [ ] 缓存键含 `facts.v`（版本变了整份失效；§6）

## F. 观测（口径错了比没数据更糟）

- [ ] 三个延迟指标必须同时存在：`p95all` / `p95ok`（只算成功）/ `good3s`（成功且 ≤3s）（§10）
- [ ] 北极星：`firstTry = down > 0`、`firstPage = down ≥ 4096`、`gap = 两者之差`（§10）
- [ ] 计数器：`v6c`（v6 客户端）、`smN`/`smD`（小响应来自中继/直连）、`factSkip`（闸门拒因分布）、`psDrop`（批量写丢弃）、`ftGray`（2048–4096 灰带）
- [ ] 调试口：`?rt=<host>`、`?facts=<kind>`、`?blk=<host>`、`?fam=<host>`、`?plan=1`
- [ ] `/health` 必须暴露 `bizSweeps`（自愈次数）与 `blkMute`（静默中的 host 数），否则「业务 403 被误判」没有反证（§10）
- [ ] 软化的代价上限：同一场景软降权 ≥90%、且与硬排除的差 ≤6 点（§15.7 A11；实测 92.8% vs 97.5%）
- [ ] **`/health` 的计数器是每 isolate 一份**，单点读数不能当全局结论（§12 的教训）

## G. 订阅

- [ ] 结构：`🅰 模式 → 🚀/⚡ (fallback) → 📡 目标实测 → 🌐 入口竞速 → 🔁 中继竞速 → 📛 域名入口`；**每个模式一套竞速组**（§7）
- [ ] 条目预算默认 ≤36（`?full=1` 才到 46–60）；无 80 端口；`ip-version: ipv4`；server 用 CF 边缘 IPv4 字面量（§7）
- [ ] 健康检查节奏：入口 180s / 中继 300s / 目标实测 300s 且成员 ≤4（≈8000 次/天，占额度 8%；§7）
- [ ] `?tu=` 组是**唯一**能区分出口族的客户端手段；`/health` 型竞速组与无组等价（§7）
- [ ] `?tu=` 默认关闭，开启时告知用户「每 5 分钟几条真实请求」（§7）

## H. 迁移

- [ ] 六步、每步一个开关、**关掉后逐位等于上一步**（§9、§9）
- [ ] S1（只加事实层）的验收标准是「指标不变」：`firstPage` 波动 <6pt（§9）
- [ ] S2 上线 2 小时未见 +30pt ⇒ 回滚查证据闸门（§9）
- [ ] S4 `p95ok` 涨 >60ms ⇒ 退回不阻塞读（§9）

## H2. 引用数字时的规矩

- [ ] 每个数字标证据等级：**A 实测 / B 仿真 / C 推理**（§12）；标不出的删掉
- [ ] B 级数字必须连输入一起引用（如「3 条 v4 / 1 条被拒 → 93.9%」）
- [ ] 对外承诺只用 §8 的条件式，不写裸数字

## I. 明确不做（做了会更差）

- [ ] 不做「`v6 = 封锁`」的二元事实（p≈12.5%，不是 0；§12）
- [ ] 不做「跨 isolate 共享 `ttfb`/`bps`」（路径属性，§3.1）
- [ ] 不做「硬封锁跨站点共享」（7.57 事故：97% → 2/20；§12）
- [ ] 不做「确定性选最优先验」（§6：14.3%）
- [ ] 不做「吞吐优化」当池内差异 <2x 时（噪声带 1.7x，§5.1）
- [ ] 不引入任何 userland TLS / 自研握手（免费计划 CPU 装不下；§12）
