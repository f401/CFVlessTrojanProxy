# v8 实现清单

> 这份文档只做一件事：把 `docs/架构重设计_v8.md` 里**被实验证明过**的硬规则抽成一页可勾选的清单。
> 每条都带「数字 + 出处」；没有出处的不许加进来。实现时逐条打勾，评审时逐条核对。

## A. 事实层（DO）

- [ ] 表结构：`facts(kind TEXT, k TEXT, at INTEGER, j TEXT, PRIMARY KEY(kind,k)) WITHOUT ROWID` + `idx_facts_at(kind,at)`（§28）
- [ ] 唯一写入口：`INSERT … ON CONFLICT(kind,k) DO UPDATE SET at=excluded.at, j=excluded.j WHERE excluded.at > facts.at`（**严格 `>`**，相同 `at` 也忽略，防两 isolate 乒乓；§28）
- [ ] 五类事实与 TTL：`dns` 24h / `eg` 6h / `ps` 45min / `blk` 90min / `dead` 30min（§4.2、§22.4；`blk` 与 `ps` 寿命不同是故意的）
- [ ] 容量上限：`dns 512 / eg 512 / ps 512 / blk 1024 / dead 256`；**淘汰在写入之前跑**，只删本 kind、按 `at` 升序（§17.2、§28）
- [ ] 读取：`GET /meter/facts?s=<kind>&since=<ts>` **按 kind 分片**；单 kind 一次 <8KB（整库最坏 ~250KB，不能一次全拉；§28）
- [ ] 写入：**isolate 结束即冲写**（一次 ≤3 行），不设 16 条门槛（§37.1 D13：3 连 isolate 永远攒不满，等于一条不写）；≤64 行/次；>20 万连接/天开抽样，`k = ceil(连接数/30万)`，丢弃计入 `psDrop`（§37.3）
- [ ] `SQLITE_FULL` 捕获后降级不抛错；`since` 只在成功应用后前移（§28）

## B. 判定（写入闸门）

- [ ] 只有 `commitFact` 一个写入口，规则顺序固定：节流 → 回显 `eg` → 中继坏 `dead` → `429` 退避 → 站点级 → `blk` → 完整响应 `ps(ok)` → 零字节（§26）
- [ ] `tiny = down > 0 && down ≤ 2048 && down < 0.2 × bigTypical[host]`（**不是 ≤64**：封锁页已是 737B HTML；§19.2）
- [ ] `blk` 需要三件同时成立：`tiny` + 同 120s 窗口有 ≥20KB 对照 + **三个批次**（间隔 ≥60s）；三批不是两批（§35.3：假阳性 0.25% → 0.01%）
- [ ] lk 键 ${host}|；**直连腿永不可写**（CF 边缘身份不可归属）；全通道 4xx / 429 永不写（§19.4）
- [ ] ps 允许吃 B 级负样本（单批 	iny + 同窗口 ≥20KB 对照），但只做「机会归一化的失败计数」；负样本步长与正样本同阶（§38.3 D14）
- [ ] 同质化检测：候选 p 估计 max/min < 1.5 时视为同质，改走轮换 + 康复通道（§38.4）
- [ ] 成功判据是 `down > 64`（拿到完整响应），**不是 2xx**（`api.github.com` 415+1277B 是正常业务；§15 D4）
- [ ] `tiny` 响应**不写 `ps(ok=0)`**（`example.com` 932B 会误伤），只加计数（§26）

## C. 选路

- [ ] 代价：`transport / max(0.08, p)`；`tput = ttfb + 512KB / max(32KB/s, cap × 64KB/s)`、`lat = ttfb`（§7、§24）
- [ ] `p = (q_ps / 255) × 0.6 + prior × 0.4`，`prior = eg==4 ? 0.95 : 0.5`（§22.4、§19.3）
- [ ] 排序链：`dead 排除 → blk 排除 → 代价 → 探索`；**`eg` 只做偏置，永不做硬过滤**（§21：硬过滤 14.3%，比盲选还差）
- [ ] `blk` 全部命中时走 `leastBad()`，**永不返回空**（§15 D1）
- [ ] 探索：8% 请求随机（§29 天花板分解）；**康复通道**：每 20 条请求 1 条走「分数最低但历史上有整页」的中继（§35.3，否则被误判的节点永远回不来）
- [ ] `ps` 窗口：初值 8、上限 32；连续 3 次成功把 n 重置为 4（§35.1）

## D. 预算与并发

- [ ] 单轮 48 子请求：准入 32–40 / 审计 6–8 / 退款 4 / 入口 0–4（§8）
- [ ] **`connect()` 全局 6 个**，探测按**波次**限流：一波用户连接最多 2 次探测（§32：40 并发 p95 675 → 250ms）
- [ ] `probeWave` 也要约束 `cold+empty` 的后台回显（§32.4）
- [ ] `readFacts` 四条契约：全有或全无 / 只在冷 isolate 第 1 条连接阻塞 / 每 isolate 10 分钟最多 1 次读（失败 60s 内不重试）/ 陈旧 <1h 仍用并标 `stale`（§20.5）
- [ ] 并发读 **single-flight**（同 isolate 共享同一个 Promise；§32.3）
- [ ] `connect()` 一律 `withTimeout(2500)`，超时后**关闭迟到的 socket**（7.86 的泄漏教训；§13.3）

## E. 冷启动

- [ ] 三档：warm 正常 / cold+facts **最多阻塞 200ms** / cold+empty 不阻塞、后台补 1 条回显（§20.2、§30.2）
- [ ] colo 缓存 TTL **120s**（60s 在低流量下命中率只有一半；§30.3）
- [ ] 缓存键含 `facts.v`（版本变了整份失效；§21.2）

## F. 观测（口径错了比没数据更糟）

- [ ] 三个延迟指标必须同时存在：`p95all` / `p95ok`（只算成功）/ `good3s`（成功且 ≤3s）（§33.3）
- [ ] 北极星：`firstTry = down > 0`、`firstPage = down ≥ 4096`、`gap = 两者之差`（§20.1）
- [ ] 计数器：`v6c`（v6 客户端）、`smN`/`smD`（小响应来自中继/直连）、`factSkip`（闸门拒因分布）、`psDrop`（批量写丢弃）、`ftGray`（2048–4096 灰带）
- [ ] 调试口：`?rt=<host>`、`?facts=<kind>`、`?blk=<host>`、`?fam=<host>`、`?plan=1`
- [ ] **`/health` 的计数器是每 isolate 一份**，单点读数不能当全局结论（§12 的教训）

## G. 订阅

- [ ] 结构：`🅰 模式 → 🚀/⚡ (fallback) → 📡 目标实测 → 🌐 入口竞速 → 🔁 中继竞速 → 📛 域名入口`；**每个模式一套竞速组**（§27.1）
- [ ] 条目预算默认 ≤36（`?full=1` 才到 46–60）；无 80 端口；`ip-version: ipv4`；server 用 CF 边缘 IPv4 字面量（§27）
- [ ] 健康检查节奏：入口 180s / 中继 300s / 目标实测 300s 且成员 ≤4（≈8000 次/天，占额度 8%；§27）
- [ ] `?tu=` 组是**唯一**能区分出口族的客户端手段；`/health` 型竞速组与无组等价（§31.1）
- [ ] `?tu=` 默认关闭，开启时告知用户「每 5 分钟几条真实请求」（§31.4）

## H. 迁移

- [ ] 六步、每步一个开关、**关掉后逐位等于上一步**（§17.5、§34.3）
- [ ] S1（只加事实层）的验收标准是「指标不变」：`firstPage` 波动 <6pt（§34.2）
- [ ] S2 上线 2 小时未见 +30pt ⇒ 回滚查证据闸门（§34.3）
- [ ] S4 `p95ok` 涨 >60ms ⇒ 退回不阻塞读（§34.3）

## I. 明确不做（做了会更差）

- [ ] 不做「`v6 = 封锁`」的二元事实（p≈12.5%，不是 0；§13.6/§13.8）
- [ ] 不做「跨 isolate 共享 `ttfb`/`bps`」（路径属性，§16.5）
- [ ] 不做「硬封锁跨站点共享」（7.57 事故：97% → 2/20；§13.4）
- [ ] 不做「确定性选最优先验」（§21：14.3%）
- [ ] 不做「吞吐优化」当池内差异 <2x 时（噪声带 1.7x，§24）
- [ ] 不引入任何 userland TLS / 自研握手（免费计划 CPU 装不下；§13.2）
